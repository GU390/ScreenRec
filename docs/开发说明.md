# 屏幕录像 ScreenRec

一个**零依赖、零安装**的 Windows 屏幕录像小工具：整屏录像 / 矩形区域录像，输出 **MP4 (H.264)** 或 **AVI (MJPEG)**。

- 单文件 exe（66 MB），**不需要装 .NET，不需要装任何解码器**
- 抓屏用 GDI+（`CopyFromScreen`），编码用系统自带的 JPEG 编码器，AVI 封装是自研的 MJPEG/AVI 封装器
- **AVI 模式全程零外部进程**；**MP4 模式**把 JPEG 帧实时喂给 ffmpeg 边录边压（ffmpeg 是可选依赖）
- 无注册表改动、无网络访问

---

## 一、怎么用

双击 `ScreenRec.exe` 打开主面板。

| 模式 | 说明 |
|---|---|
| **整屏录制** | 录下所选显示器的整个画面（1920×1080 物理像素，与屏幕原始分辨率一致） |
| **矩形区域** | 点「框选区域…」→ 屏幕上铺一层半透明遮罩 → 拖拽框选 → 回车确认 |

拖拽框选时：

- 选区内**拖动** = 移动选框
- 拖**四角** = 缩放选框
- `回车` = 确认　`Esc` = 取消　`R` = 重新框选

点「开始录像」录制，点「停止录像」结束并保存。

### 输出格式（输出区三选一）

| 选项 | 产物 | 需要 ffmpeg？ |
|---|---|---|
| **AVI (MJPEG) · 零依赖** | `录像_20261021_141708.avi` | 否 |
| **MP4 (H.264) · 体积小**（默认） | `录像_20261021_141708.mp4` | **是** |
| **两者都要** | `.mp4` + `.avi` 母版 | 是 |

- MP4 模式：**边录边压**，录完立刻得到 MP4，不用等二次转码
- MP4 成功后，程序会**自动删掉中间 AVI**；选「两者都要」则两份都保留（母版是 MJPEG，可作为二次加工的素材）
- 管道中途出问题（ffmpeg 崩了 / 磁盘满），**AVI 母版仍在**，不会丢录像
- 找不到 ffmpeg 时不会静默失败：会弹窗说明并自动回落到 AVI 模式

### 悬浮提示条

录制时屏幕右上角会出现一个小提示条：录制时长、分辨率、已录帧数、文件大小、实时预览画面，以及「停止录像 (F9)」按钮。

- 它**不会**被录进画面（录制时该区域被排除）
- 不想要可以在「选项」里关掉

### 快捷键（全局，程序不在前台也生效）

| 键 | 作用 |
|---|---|
| `F9` | 开始 / 停止录像 |
| `F10` | 打开区域框选 |
| `Esc` | 停止录像 |

### 设置

参数、输出目录、选项都记在**程序同目录的 `settings.json`**，下次打开自动恢复。删掉它就恢复默认。
（程序目录不可写时，例如放在 `Program Files` 下，会自动改存 `%APPDATA%\ScreenRec\settings.json`。）

## 二、MP4 (H.264) 输出

### ffmpeg 是可选依赖，怎么找到它

面板「输出」区有一行 ffmpeg 路径，启动时自动探测，探测顺序：

1. 你在面板上手动「选择…」指定的路径（存进 `settings.json`）
2. `ScreenRec.exe` 同目录 / 同目录的 `ffmpeg\` 或 `bin\` 子目录
3. 系统 `PATH`
4. 从 exe 目录**往上 5 层**扫 `ffmpeg-*` 目录下的 `bin\ffmpeg.exe`
   （本机 `Miscellaneous\ffmpeg-9.0.2-essentials_build\bin\` 就是这样被找到的）
5. 常见安装位置（`C:\Program Files\ffmpeg\bin`、WinGet Links 等）

面板上会直接显示最终用到的绝对路径：

- 绿色路径 = 找到了，MP4 可用
- 橙色「未找到 —— MP4 不可用，将只输出 AVI」= 没找到

**想做成完全便携**：把 `ffmpeg.exe` 拷到 `ScreenRec.exe` 同一个文件夹即可（不需要整个 ffmpeg 目录）。

### 实际用的编码参数

```
ffmpeg -hide_banner -loglevel error -y
  -f image2pipe -vcodec mjpeg
  -use_wallclock_as_timestamps 1 -framerate <设定帧率> -i pipe:0
  -c:v libx264 -preset veryfast -crf <N>
  -vf scale=in_range=full:out_range=tv,format=yuv420p
  -movflags +faststart
  <输出.mp4>
```

几个关键点：

| 参数 | 为什么这么设 |
|---|---|
| `-preset veryfast` | 编码速度约 **3.75× 实时**（1080p 6 秒素材用 1.6 秒压完），边录边压才不拖慢录制 |
| `-crf` | 由面板「画质」滑块映射：画质 40 → CRF 30，画质 95 → CRF 18 |
| `-use_wallclock_as_timestamps 1` | **不加这行会变快进**。实际帧率低于设定值时（抓屏达不到 30fps），MP4 会按设定帧率算时间轴，6 秒的片子只播 4.7 秒。加了之后偏差从 24% 降到 5% |
| `-movflags +faststart` | moov 索引挪到文件头，边下边播、网页/文档里预览不用等整个文件 |
| `format=yuv420p` | 兼容性优先，手机、微信、Office、剪映都能直接用 |

### 体积对比（本机实测，1080p）

| 场景 | AVI (MJPEG) | MP4 (H.264) | 压缩比 |
|---|---|---|---|
| 动态画面（满屏滚动/动画） | 6.92 MB | 2.75 MB | **2.52×** |
| 静态桌面（大部分画面不动） | 14.86 MB | 0.585 MB | **25×** |
| 静态桌面（另一轮实测，6.3 秒） | 19.97 MB | 0.245 MB | **81×** |

静态场景压缩比特别高（且波动大），是因为 MJPEG **每帧独立压缩**，画面不动也要把整帧重新存一遍；H.264 会复用前后帧，所以几乎不涨体积。

**结论**：要发给别人 / 插进文档 / 上传，**用 MP4**；要留素材做后期，**选「两者都要」**。

### 画质一致性（MP4 vs AVI 母版逐帧比对）

抽同一时刻第 30 帧做像素级比对：

| 指标 | 实测 |
|---|---|
| 平均像素差 | **0.98**（0~255 量纲） |
| 差异 > 10 的像素占比 | **0.05%** |
| 时间轴偏差 | 5% |

肉眼无法分辨，压缩没有丢画面。

**时间轴是实测过的**（不是推断）：把 MP4 的 72 帧时间戳拉出来，首尾跨度 5.867 秒、有效 12.1 fps，和真实录制耗时 6.34 秒吻合 —— **没有变快进**。
（`ffprobe` 报 `r_frame_rate=15/1` 是它从容器头猜的**名义**帧率，不是实际播放速率，看 `duration` 和帧时间戳才准。）

## 三、输出文件（AVI 模式细节）

- 格式：**AVI (MJPEG)**，每帧一张 JPEG
- 命名：`录像_20261021_141708.avi`
- 头部写的是**实际达成的帧率**（不是设定值），所以回放时间轴和真实录制一致
- 兼容性：Windows 媒体播放器 / 电影和电视 / VLC 都能直接播
- 自研封装器产出的 AVI 已通过 **ffmpeg 独立解码验证**（MJPEG / 1920×1080 / 91 帧 / 6.12 秒，第三方通用工具交叉验证）

### 体积估算（1080p，15 fps，AVI）

| 画质 | 码率 | 1 分钟约 |
|---|---|---|
| 40 | ~3 Mbps | ~23 MB |
| 70 | ~6 Mbps | ~45 MB |
| 95 | ~14 Mbps | ~105 MB |

MJPEG 是**每帧独立压缩**，画质调到 95 以上只是让文件变大，收益很小。**推荐 70~85**。
（用 MP4 模式的话，画质滑块换成控制 CRF，同样数值下体积会小一个数量级。）

## 四、实测数据（本机，1920×1080，15 fps）

| 项 | 实测 |
|---|---|
| 实际帧率 | 14.2 ~ 14.9 fps（设定 15） |
| CPU 占用 | 平均约 23% 单核（峰值 87% 出现在启动首帧） |
| 内存 | 83 MB |
| 启动开销 | 约 0.55 s（含 GDI+ 编码器预热） |
| AVI 输出码率 | 1080p/画质80 约 8 Mbps |
| MP4 编码耗时 | 1080p 6 秒素材 ≈ 1.60 s（≈3.75× 实时） |

想更省资源：把帧率降到 10、把画质降到 60，CPU 能降到 10% 以下。

## 五、已知限制

1. **多显示器缩放不一致时，跨屏框选会有偏差**（本机单屏 125% 缩放，无此问题）
2. **录不到鼠标指针**（GDI 抓屏本来就不含光标）
3. **录的是「画面」，不是「操作」** —— 窗口动画、DWM 合成效果能录到，但受保护视频（DRM）会是黑屏
4. 矩形区域模式下，如果选区正好被悬浮条盖住，那块是「录制开始瞬间的静态画面」（不是实时更新）
5. 输出目录不可写时会提示失败，不会静默丢数据
6. **MP4 模式需要 ffmpeg**；ffmpeg 不可用时会弹窗回落到 AVI，不会静默失败
7. 面板上的「画质」滑块在 AVI 和 MP4 两种模式下含义不同：AVI 是 JPEG 质量分，MP4 是 CRF 映射

## 六、命令行自测（不用点界面）

```
ScreenRec.exe --selftest --seconds 3 --out D:\test.avi --fps 15 --quality 80
               [--rect x,y,w,h] [--exclude x,y,w,h] [--mp4 D:\test.mp4] [--log D:\test.log]
```

不开界面，录一段指定时长并打印统计。参数：

| 参数 | 说明 |
|---|---|
| `--seconds N` | 录制时长（秒） |
| `--out <路径>` | 输出 AVI 文件（必填） |
| `--fps N` | 帧率，默认 15 |
| `--quality N` | 画质 40~95，默认 80 |
| `--rect x,y,w,h` | 录制区域（物理像素），不填则整屏 |
| `--exclude x,y,w,h` | 排除区域（不录进去），模拟悬浮条 |
| `--mp4 <路径>` | 同时输出 MP4（自动找 ffmpeg，找不到就跳过） |
| `--log <路径>` | 把输出同时写到日志文件 |

```

```

### 重新构建

本机没有系统级 .NET，用工作目录里的便携 SDK：

```powershell
$dn = "D:\Ksoftware\MiniMax_Desktop\Miscellaneous\dotnet-sdk-10.0.402-win-x64\dotnet.exe"
$proj = "D:\Ksoftware\MiniMax_Desktop\Miscellaneous\tools\sys\ScreenRecorder\ScreenRec.csproj"

# 调试版
& $dn build $proj -c Release

# 发布单文件自包含 exe
& $dn publish $proj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true -p:DebugType=none `
  -o ".\publish"
```

### 排障

- 崩溃日志：程序同目录 `screenrec_error.log`
- 交互事件日志：设环境变量 `SCREENREC_DEBUG=1` 后运行，会把框选层的鼠标/键盘事件写到 `screenrec_ui.log`
- MP4 没出来：先看面板 ffmpeg 那行是不是绿字；再确认 `ffmpeg.exe` 里带了 **libx264**（`ffmpeg -version` 的配置行里要有 `--enable-libx264`）
